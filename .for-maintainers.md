# For maintainers

## What this is

A folder of static files. GitHub Pages serves them. That is the entire system.

```
/index.html                    the front page, lists every project
/style.css                     styles for the front page only
/.nojekyll                     stops GitHub rewriting anything
/projects/pod-07/index.html    a project page
/projects/pod-07/style.css     that project's styles
/projects/pod-07/images/       that project's pictures
```

A URL maps to a file. `https://globalai.github.io/projects/pod-07/` serves
`projects/pod-07/index.html`. There is nothing else to know.

## Turning it on

Settings, Pages, Source: **Deploy from a branch**. Branch `main`, folder `/ (root)`. Save.

No Actions, no workflow file, no build, nothing to install, nothing that can fail at build time.
The only failure mode left is a page that looks wrong, on one project, visible only on that
project.

`.nojekyll` matters. Without it GitHub runs the files through Jekyll, which quietly ignores any
file or folder whose name starts with an underscore. Leave the file in place.

## Why no build step

Because the students have never used a terminal, npm, or git. Any build step means a pipeline that
can go red, and a red cross a first year student cannot read or fix. Plain HTML has no such state.
They edit a file, the file is the page.

The cost is real and worth naming: the front page card list is hand written HTML. Adding project 18
means copying a block in `index.html`. With 17 to 40 projects that is a minute of work a few times
a year, which is cheaper than a build system everybody has to trust.

## Adding project 18

1. Copy any existing folder: `cp -R projects/pod-17 projects/pod-18`
2. In `projects/pod-18/index.html`, change `Pod 17` to `Pod 18` in the `<title>` and the `<h1>`
3. In `projects/pod-18/images/cover.svg`, change the number in the two text lines
4. In the root `index.html`, copy any card block and change `pod-17` to `pod-18` and the heading

All four steps work through the GitHub web interface, so this does not need a maintainer with a
laptop set up.

## Naming

| Thing | Rule |
| --- | --- |
| Project folders | `pod-NN`, two digits, assigned once, never renamed or reused |
| Project name | fixed, `pod-07` is shown as "Pod 7" |
| Public URL | fixed, `/projects/pod-07/` |
| The page file | always `index.html`, never anything else |
| Pictures | lowercase, no spaces |
| The card picture | `images/cover.svg` ships as a placeholder, replace with `cover.jpg` |

The name and the URL are fixed on purpose. It means no renaming, no redirects, no two teams
claiming the same word, and an address that is safe to print. Teams put their real project name in
the `<h1>` of their own page.

## Repository settings

- Give every student write access.
- Leave branch protection on `main` **off**. Requiring pull requests adds branches, reviews and
  merge conflicts to a workflow whose entire value is having none of them.
- The blast radius of any mistake is one folder, and every version is recoverable through
  **History**.

## Previewing locally

Only if you want to. Opening `index.html` by double clicking works for most things.

```bash
python3 -m http.server 8000     # then open http://localhost:8000
```

## What was deliberately left out

A build step, a template engine, Markdown, front matter, tests, CI, pull request review, and
per project slugs. Every one of them is a thing that can fail in a way a first year student cannot
diagnose.

If the lab later wants generated pages and validated metadata, the earlier design in the repository
root has all of it, at the cost of a toolchain.
